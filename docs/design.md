# 中文写实对白短片首版设计

日期：2026-11-16。

用户已确认产品方向和实施路线。本文保留完整产品设计；当前独立仓库 yingyan 交付其中第一阶段：账号、项目、剧本、角色、场景、分镜、参考图和不可变版本，以及可选的 OpenAI 文本建议。真实配音、口型、视频生成与合成属于后续阶段，尚未实现。

本仓库独立于原笔试图片演示项目。以下完整设计中的模块地址与第一阶段有差异：当前页面为 /projects、/studio/[id]，Java 接口前缀为 /api；账号采用本地 BCrypt 密码和服务端会话。以 README 和实际 API 为准。

## 1 产品目标与首版边界

面向国内用户，将故事或场景词制作成角色互相说话的真人写实剧情短片。用户能够修改一句台词或一个镜头，合成新版本，并继续查看旧版本。

首版默认：普通话、9:16、720P 合成输出，30–60 秒，两个主要角色、一个主要场景、4–12 个镜头。先以 10–15 秒双人对白样片验证模型，再扩展到完整短片。以上数量是首版产品约束，可在后续迭代放宽。

支持 AI 创建角色参考图与用户上传参考图。角色参考和声音选择必须显式确认；没有预置素材的项目也应能从文字开始。真人写实是视觉风格，系统不承诺生成的人物跨镜头完全一致，提供参考图、镜头预览和局部重做控制质量。

对话主要使用正反打、人物近景和反应镜头。单个说话镜头绑定一位说话人；双人同框镜头首版用于静态建立空间、倾听或无同步对白的动作，不提供两个角色同时开口的生成控制。通过镜头切换、画外音与停顿呈现双方交流。

不开发充值、支付、套餐、积分、订单和扣费界面。保留供应商请求标识与资源消耗日志用于排查调用；不将其构造成收费系统。真实外部 API 仍需要有效服务配置。

## 2 已确认的主流程

故事输入 → 剧本与角色确认 → 分镜编辑 → 配音试听确认 → 单镜头生成 → 镜头选择与合成 → 预览/下载 → 修改建议预览 → 新版本。

生成不是页面打开后的自动副作用。剧本、角色参考、配音和视频分别有明确的生成按钮；结构化编辑和查看历史不会自动提交外部生成请求。

第一次验收故事示例：两人在咖啡馆分别说一句话，中间有一个停顿或反应镜头。用户试听两种声音，确认人物参考图，生成镜头，合成成片，再修改其中一句台词并生成新成片。

## 3 实现路线选择

| 路线 | 收益 | 主要代价 | 决策 |
|---|---|---|---|
| 按句配音、按镜头生成、独立合成 | 能绑定声音归属，精准复用未改内容，适合局部重做 | 要管理音频时长、镜头依赖和合成 | 首版采用 |
| 直接音画联合生成整个片段 | 可探索自然表演和完整氛围 | 台词、固定音色和逐句修改的控制需额外验证 | 后续通过相同供应商接口扩展 |
| 自部署视频与口型模型 | 可控制部署和模型流程 | GPU、模型运维与推理排队显著增加首版工作 | 不作为首版依赖 |

技术方案建议优先验证阿里云百炼的文本、语音、图像及说话视频链路。模型 ID、音色 ID、地域、业务空间、输入限制由供应商能力配置提供，并通过真实样片验证后固定版本，不将“支持视频 API”视为“已达到电影表演质量”。

## 4 页面与交互

### 4.1 项目列表

展示项目名称、封面、最后编辑时间、最近成片和正在运行的任务。支持创建项目、继续编辑、打开版本历史。首版以项目隔离素材与生成任务。

### 4.2 项目创作工作台

同一项目内使用五个工作区：故事剧本、角色、分镜、制作、成片版本。顶部固定项目名、保存状态、当前编辑版本和后台任务入口。

- 故事剧本：输入故事/场景词，设定题材、目标时长，生成并编辑场景和对白。AI 生成草稿不直接覆盖用户文本，用户确认后采用。
- 角色：人物名字、外貌、服装、人物关系、参考图和声音。支持生成/上传参考图、图像适配检测、试听音色和确认版本。
- 分镜：左侧镜头列表，中间画面或视频预览，右侧当前镜头的角色、台词、景别、动作、情绪、顺序和时长。首版为镜头卡片排序，不做完整专业非线性时间轴。
- 制作：显示逐句音频、逐镜头视频、外部请求阶段、失败原因和可重试范围。单镜头失败不抹去其他镜头成果。
- 成片版本：视频预览、下载、生成时间、使用的素材版本与修改摘要。可以选旧版本作为新草稿起点，不覆盖既有成片。

桌面优先，手机可查看、修改字段、试听和触发生成。编辑状态、生成状态、查询故障分别表达。离开页面不停止后台制作；离开页面取消当前页面的查询。

### 4.3 对话修改入口

工作台下方提供项目内的修改输入，例如“第二句更犹豫”“第三镜头改近景”“第二句改成女主说”。返回一个修改预览，列出字段变化、受影响素材和复用素材。用户点击应用后更新草稿；需要生成时再通过明确按钮执行。

修改建议不能直接调用任意工具或修改其他项目。后端仅接受白名单操作，并校验角色/镜头属于当前项目、基准版本未变化；无法确定“第二句”指代时展示候选位置，不猜测执行。

## 5 核心数据与版本

新业务使用独立的 `story_` 表与 Java 模块，保留原图片任务模型的语义。产品入口建议为 `/studio`，API 为 `/api/story`。现有图片演示在当前阶段保留，作为历史实现，不把模拟图片输出包装成真实视频输出。

| 实体 | 关键数据与职责 |
|---|---|
| user / session | 内测用户名密码、密码哈希、HttpOnly 登录会话、项目归属；不依赖短信或收费账号系统 |
| project | 标题、主人、画幅、语言、目标时长、当前草稿 revision |
| project_revision | 不可变的剧本、角色版本、镜头顺序与对白快照；保存修改摘要 |
| character / character_revision | 稳定角色 ID 与可版本化的外貌、服装、参考素材、声音配置 |
| scene | 场景描述、光线、人物站位和视线关系，随项目 revision 冻结 |
| shot | 稳定镜头 ID、场景、顺序、出场角色、说话角色、景别、动作、预期时长 |
| dialogue_line | 稳定台词 ID、角色 ID、正文、情绪、语速、停顿；每个说话镜头首版绑定一句主台词 |
| media_asset | 图片/音频/视频、持有者、存储 key、时长/分辨率/编码、校验摘要、来源 |
| generation_job / job_step | 请求输入快照、依赖、阶段、租约、外部 task ID、结果、错误与重试记录 |
| shot_take | 镜头候选版本、引用的角色/音频/画面版本、供应商与输入摘要 |
| render_version | 所用 revision、选定 shot_take 列表、时间编排、输出文件和合成配置 |
| change_proposal | 基准 revision、结构化操作、影响清单、状态；应用时做版本校验 |

复用依赖摘要：台词音频取决于文本、声音配置、情绪和语速；说话视频取决于画面参考、镜头提示、音频资产与模型配置；成片取决于选定镜头、顺序、停顿、字幕、背景音和画幅。外部任务使用冻结输入，不读取持续变化的草稿字段。

“重新生成”允许相同输入产生新候选，使用新的 generation ID；“网络重试”重用同一次请求的幂等标识。不能因为输入相同就永远禁止用户重做。

## 6 声音、口型与时长

角色 ID 决定使用哪个声音，每句对白持有独立音频资产。先生成并试听对白，再根据音频真实长度计算镜头长度与停顿；不依赖 LLM 猜测精确时长。

候选 `wan2.2-s2v` 根据图片与音频生成包含口型、表情和动作的视频，不是在任意已生成视频上原位修嘴。首版以它实现单人物说话镜头，配合独立的无对白动作/反应镜头生成与 FFmpeg 编排。

按当前文档，该候选接口限定北京地域，输入图像需 400–7000 像素，音频为 WAV/MP3、低于 15MB 且短于 20 秒，并要求清晰人声和可访问的 HTTP/HTTPS 素材地址。设计默认将一句对白的音频控制在 15 秒以内，超出时拆分成多个有明确分镜的片段；最终以检测到的时长和供应商约束校验。

配音情绪参数只使用选定模型真正支持的能力。接口不支持的参数不能显示成已生效；实际效果通过试听确认。

合成阶段统一视频尺寸、帧率与音频采样率，按实际媒体时长编排字幕、停顿与画外音。检查视频是否已有音轨，只保留选定的对白音轨，避免把口型视频原音与 TTS 重复叠加。背景音最后混入，不能作为口型输入。

角色换装/换参考图会影响引用对应角色版本的镜头；声音调整影响相应音频及说话视频；单句台词修改影响该句音频、对应说话镜头、字幕和后续时间编排。用户确认新版本后只重做这些依赖，未受影响的资产继续复用。

## 7 服务边界与基础设施

- Next.js / React / TypeScript：工作台、结构化编辑、查询与播放，不承载模型密钥或制作状态的权威数据。
- Java / Spring Boot / MyBatis / MySQL：登录与归属、项目版本、依赖判断、任务编排、供应商适配、状态查询。
- 国内对象存储（首选 OSS）：保存输入与输出。应用提供受保护访问；供应商通过专门签发的短期 URL 读取允许的素材。原有依赖浏览器 Cookie 的 `/assets/...` 地址不能直接交给模型。
- FFmpeg / ffprobe：由专用渲染 worker 调用，探测素材并合成 MP4。首版可使用同一 Java 代码的独立 worker 运行模式，网页进程不执行 FFmpeg 重负载。
- 数据库队列：持久化任务与下一次查询时间，分别限制供应商提交、结果查询、下载和 FFmpeg 并发；无需首版引入 MQ。

供应商接口分为文本规划、角色/镜头图像、语音、说话视频、无对白视频。先只实现一套已验证的国内供应商配置，保持这些接口边界，避免同时维护多个未验证平台。

## 8 异步执行与恢复

任务阶段使用：QUEUED、SUBMITTING、REMOTE_RUNNING、DOWNLOADING、POSTPROCESSING、SUCCEEDED、FAILED、CANCELED、SUBMISSION_UNKNOWN。一个状态不能同时表达用户编辑进度和供应商执行进度，项目本身也不使用“所有内容都成功”的单一布尔值。

执行原则：

1. 事务创建任务和依赖，提交后才允许调度。界面立即拿到内部任务 ID。
2. 用条件更新/租约认领有限的短工作，不用线程长时间 sleep 等供应商完成。
3. 接收外部 task ID 后立即持久化，以 next_poll_at 调度查询。原图片 worker 的固定 120 秒上限和重启直接失败策略不能直接复用于真实视频。
4. 外部提交超时但不知道是否受理时，进入 SUBMISSION_UNKNOWN。优先通过供应商可用的幂等/查询机制核实；无法核实时不自动重复提交，展示可理解的待核实状态与明确的重新提交动作。
5. 有外部 task ID 的任务在重启后继续查询；已完成步骤不重做。超时、重试策略依供应商能力配置，不承诺跨系统 exactly-once。
6. 外部成功后下载到己方存储，验证文件和媒体元数据，持久化后才对用户显示素材可用。输出 URL 失效不能仅靠重新生成解决。
7. 本地取消通过终态栅栏阻止晚到结果覆盖状态；只有供应商支持时才尝试远端取消。取消按钮不承诺外部执行立即停止。
8. 合成任务只引用冻结的成功素材；缺少或过期依赖时等待用户选择或重做，不静默拿旧素材冒充新结果。

所有重试有次数和退避上限。网络错误、限流、参数不合法、内容被供应商拒绝、结果下载失败和 FFmpeg 失败分别记录，并提供对应的恢复动作。请求日志保留外部 request/task ID，不记录密钥。

## 9 接口轮廓

| 方法与路径（前缀 /api/story） | 行为 |
|---|---|
| POST /sessions，DELETE /sessions/current | 内测登录/退出 |
| GET/POST /projects，GET/PATCH /projects/{id} | 项目列表、创建与草稿保存；保存携带 expectedRevision |
| POST /projects/{id}/script-jobs | 请求故事/剧本结构化草稿，用户采用后更新 revision |
| POST /projects/{id}/characters，PATCH /characters/{id} | 角色设置与新角色版本 |
| POST /characters/{id}/reference-jobs | 生成角色参考图；上传图片另走项目素材接口 |
| POST /projects/{id}/assets | 服务端验证并持久化素材 |
| POST /projects/{id}/storyboard-jobs | 请求可编辑的分镜草稿 |
| PATCH /projects/{id}/shots | 以 revision 保存镜头、对白和顺序 |
| POST /dialogue-lines/{id}/audio-jobs | 生成该台词的音频版本 |
| POST /shots/{id}/takes | 请求新的镜头候选，冻结输入版本 |
| GET /jobs/{id}，POST /jobs/{id}/cancel | 查询任务与请求取消；查询不推进生成业务 |
| POST /projects/{id}/renders | 用选定成功镜头创建不可变成片版本 |
| GET /projects/{id}/versions | 查询所有成片及对应 revision |
| POST /projects/{id}/change-proposals | 对自然语言修改生成白名单操作预览 |
| POST /change-proposals/{id}/apply | 校验基准 revision，原子应用；不自动触发全部制作 |

所有项目关联资源均校验归属。并发编辑冲突返回 409 和最新 revision，界面允许查看差异，不静默覆盖。创建任务返回 202 与内部任务 ID；外部任务参数错误不能伪装成成功。

## 10 真实接入配置与验收前提

需要部署侧配置百炼地域/业务空间/模型 ID/API Key、OSS bucket/访问凭据、MySQL 和 FFmpeg 路径。密钥由服务器环境变量或密钥服务提供，不写入仓库和浏览器。

模型可用性、音色列表和素材规范应通过能力查询与小样实测确认。当前只核实文档，尚未验证用户账号有调用权限，也没有进行真实生成调用。设计批准后的实施可以先完成业务与适配器；真实成片验收必须使用有效配置，模拟结果仅能作为显式演示，不能标记真实验证通过。

调用外部生成需用户明确点击生成。没有 API 配置时提供“服务未配置”的状态、草稿编辑和输入校验，不提交假任务。业务开发不依赖先建设平台计费模块。

## 11 测试与验收

自动化测试使用可控的供应商协议替身来覆盖超时、任务 ID 保存、重启后恢复、重复回调、结果过期和下载失败，测试重点为本项目编排，不把这些测试说成真实模型画质验证。

必测：

- 两个角色的声音 ID、音频和说话镜头不串扰。
- 台词音频时长决定编排；过长台词触发拆分提示。
- 修改一句台词仅使依赖音频、镜头与合成失效，不重做无关镜头。
- 用已有素材改变顺序/字幕只触发合成；无关镜头资产 ID 保持不变。
- 旧成片固定引用旧素材，后续编辑不改变旧文件和版本详情。
- 新旧 revision 冲突、跨用户读取和请求修改被正确拒绝。
- 供应商已受理但本地响应丢失时不自动重复提交；持有外部 task ID 的任务重启后继续查询。
- 查询暂不可用时保留上次状态；页面卸载取消请求；多个镜头任务和成片任务不互相覆盖。
- FFmpeg 输出可用 MP4，能播放且无重复对白、台词截断与字幕越界；单镜头失败可独立重做。

真实验收分两关：先人工检查 10–15 秒的双人对白样片（角色/声音归属、中文发音、口型、切镜与人物连续性）；再完成一条 30–60 秒短片，并修改一句台词和一个镜头，各自产生可播放的新版本。画质与表演由样片评估，不只以 HTTP 成功判定。

## 12 实施分段

1. 项目与结构化创作：内测身份、项目、剧本/角色/分镜 CRUD、revision 与素材归属、页面保存闭环。
2. 单镜头真实制作：文字规划/参考图/语音适配、人物图像检测、供应商任务提交查询、资源下载与声音试听，完成双人对白样片。
3. 多镜头成片：候选选择、ffprobe 校验、FFmpeg 合成、字幕/停顿/可选背景音、成片版本。
4. 修改闭环：自然语言修改预览、依赖失效判断、局部重做、新旧版本浏览与完整验收。

每一段产出可运行、可单独验证的业务结果；第 2 段真实样片决定模型路线是否继续，不先建设复杂模型路由或收费模块。
